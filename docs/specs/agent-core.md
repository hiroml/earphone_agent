# 仕様: エージェント本体（agent core）

- ステータス: ドラフト（テキスト試作 `poc/agent-cli` 実装済み）
- 日付: 2026-11-23
- 関連要件: F-10, F-11, F-12, F-14, F-15, N-01, N-03

## 概要
本人の発話テキストを受け取り、Claude が必要に応じてツール（検索・調査・ToDo）を使い、イヤホンで読み上げる短い応答を返す。

## ユーザーストーリー
- 歩きながら疑問を口にしたら、調べて要点だけ耳で教えてほしい。
- 「〜しなきゃ」と言っただけで ToDo に入っていてほしい。
- ちょっとした悩みに、短く具体的なアドバイスがほしい。

## 振る舞い
### 正常系
1. 入力は `Utterance(text, speaker)`。`speaker == SELF` のときだけ Claude API に送る（ADR-0002）。
2. ユーザーメッセージの先頭に現在日時を付ける（期限の推定用。システムプロンプトには入れずキャッシュを保つ）。
3. Claude がツールを選ぶ:
   - `web_search` / `web_fetch`（サーバーツール）: 調査
   - `add_todo` / `list_todos` / `complete_todo`（クライアントツール、`strict: true`）: ToDo
4. 応答は 2〜3 文の話し言葉。Markdown・URL・絵文字なし。
5. 会話履歴は API の応答をそのまま保持する（改変すると thinking ブロックが無効になるため）。

### 例外・エッジケース
- 他人・判定不能の発話: 送信せず `None`（ローカルにも残さない）
- 拒否（`stop_reason: refusal`）: サーバー側フォールバックでも拒否されたら定型文で返す
- ツールエラー: `is_error: true` の tool_result を返し、モデルに言い直させる
- ループ上限 10 回で打ち切り
- 意図不明: 推測で動かず一つだけ聞き返す（プロンプトで指示）

## 音声 UX
- 発話例: 「金曜までに田中さんに見積書送らないと」
- 応答例: 「田中さんに見積書を送る、をToDoに入れました。期限は金曜の27日です。」

## プライバシー
- 送信するのは本人の発話の文字起こしのみ。音声データは送らない。
- ToDo は端末ローカル保存。
- web_search の検索語は Anthropic 経由で検索エンジンに渡る。

## 受け入れ条件
- [x] 本人以外の発話は API に送られない（テスト済み）
- [x] 明示依頼なしの「やらなきゃ」で ToDo が登録される（実機 API で確認）
- [x] 調べものに web_search で答える（同上）
- [x] 直前の文脈を踏まえて答える（同上）
- [ ] 発話終了から音声応答開始まで 2 秒以内（N-01）→ 未達（現状 4〜12 秒）

## 未決事項
- **レイテンシ:** 候補は次のとおり。測定して決める。
  - ストリーミングで、最初の 1 文から TTS を始める
  - 検索系は「調べます」と先に返す
  - effort を low にする
  - モデルの使い分け（モデル選択はユーザーが判断）
- 受動モード: 話しかけていない独り言（例「牛乳切れてた」）もエージェントに送るか。毎回 API を呼ぶとコストが増えるので、端末側で「ToDo らしさ」を判定してから送る案もある。
- ToDo の保存先: リマインダー（EventKit）連携にするか。
- エージェントを動かす場所: iPhone から直接 API を呼ぶか、サーバー経由にするか（open-questions Q6）。iPhone 直結なら Swift で Messages API を HTTP で呼ぶ実装になる。
