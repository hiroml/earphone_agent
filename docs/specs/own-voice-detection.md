# 仕様: 自分の声の判別と端末内文字起こし（検証）

- ステータス: 検証中（PoC `poc/ios-bg-mic` に実装）
- 日付: 2026-11-23
- 関連: ADR-0002、open-questions Q4・Q5、[spec: agent-core](agent-core.md)

## 概要
イヤホンのマイクで拾った音声を端末内で文字にし、それが「ユーザー本人の発話か」を判別する。本人の発話と判定したものだけをエージェント（クラウド）に渡す（ADR-0002）。

## 仮説
- H1: Liberty 5 は通話用のノイズ低減で口元の声を強調する。そのため、本人の声は他人や TV よりはっきり大きく入る。
- H2: その結果、他人や TV の声はほとんど文字にならない。
  - 本人の判別には有利。
  - 「周囲の会話を拾う」用途には不利。
- H3: H1 が成り立てば、音量の閾値だけで実用的に判別できる。成り立たなければ、声紋による話者照合（例: Picovoice Eagle）を追加で検証する。

## 検証方法
- iOS 26 の SpeechAnalyzer / SpeechTranscriber（ja-JP、端末内処理）で文字起こしする。
- 確定した文ごとに、その間の音量統計を記録する（最大値、閾値超えの平均、閾値超えの時間）。
- 正解ラベル（自分 / 他人 / TV / 混在 / 無音）は、試験者が画面で手動で付ける。
- 入力は、イヤホン（HFP）と iPhone 本体のマイクで比較する。
- 試験手順は PoC README の S1〜S6。

## プライバシー
- 音声も文字起こしもサーバーに送らない（端末内のログのみ）。
- 試験で第三者に話してもらう場合は事前に同意を得る。ログは git 管理外（`results/`）に置く。

## 受け入れ条件（検証の完了条件）
- [ ] S1〜S4 のログが取れている（各ラベル 5 文以上）
- [ ] 自分 / 他人 / TV ごとの音量分布と、文字になった割合を集計できている
- [ ] H1〜H3 の成否を判断し、次の方針（音量閾値 / 声紋照合 / 本体マイク併用）を決める（必要なら ADR）

## 未決事項
- 音量の閾値は人・環境ごとに調整が必要か（初回に自分の声で較正する、など）
- 文字起こしの結果が確定するまでの遅延（エージェントの応答速度に直結する）
