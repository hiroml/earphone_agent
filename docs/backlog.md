### B-10 UI の改修（機能ごとの画面）
- **要望:** 調査・音楽検索・ToDo・設定など、機能ごとにアイコンを用意し、それぞれの画面で内容を確認できるようにしたい。
- **優先度:** 未定
- **メモ:**
  - いまのアプリは検証用（ログ表示中心）。製品版の UI は別アプリとして作り直す想定。
  - 構成案は、下部のタブバー（ホーム / 調査 / 音楽 / ToDo / 設定）。アイコンは SF Symbols を使えば、素材を作らずに済む。
  - 調査の履歴や ToDo を表示するには、エージェントの結果を端末に保存する仕組みが要る（B-02 との統合）。
  - モバイルの技術スタック（現在未決）を決める必要がある。検証の結果、音声処理はネイティブ（Swift）が有利なので、SwiftUI で作るのが自然 → ADR を書く。
- **次の一手:** 画面一覧と、各画面に出す内容を仕様（`docs/specs/app-ui.md`）にまとめる。ラフ画面も作る。

### B-12 音楽の検索（周囲で流れている曲を特定）
- **要望:** 後ろで流れている音楽を探す機能が欲しい。
- **優先度:** 未定
- **メモ:**
  - Apple の **ShazamKit** で、マイクの音から曲を特定できる。端末内で音の特徴を作り、Shazam のカタログと照合する仕組み。
  - ⚠️ **イヤホンのマイクは周囲の音楽を消してしまう可能性が高い**（通話用ノイズ低減のため）。音楽検索のときだけ iPhone 本体のマイクに切り替える設計が必要になりそう（B-03 の S5 で傾向が分かる）。
  - ShazamKit を使うには、Apple Developer のサイトでアプリごとに機能を有効化する必要がある。**無料の Apple ID で使えるかは未確認**（年 99 USD の有料登録が必要かもしれない）。
  - 起動方法の案: 「この曲なに？」と話しかける → エージェントのツールとして呼び出す。
- **次の一手:** ShazamKit の利用条件（無料 Apple ID で使えるか）を調べる → PoC に組み込む。

### B-13 AI を iPhone 内で動かす（ローカル LLM）
- **要望:** iPhone のローカルで実行できないか。分析する内容によってはローカル LLM を使うことも検討したい。
- **優先度:** 未定
- **メモ:**
  - ⚠️ iOS 26 標準の端末内 LLM（**Apple Foundation Models**）は Apple Intelligence 対応機種が必要。**iPhone 15（無印）は対象外**（15 Pro 以降が必要）なので、検証機では使えない見込み（要確認）。
  - 代替案: llama.cpp や MLX Swift で、小型のオープンモデル（1〜3B 程度、量子化）を動かす。
    - iPhone 15（メモリ 6GB）でも動く可能性はある。
    - 一方で、日本語の品質・発熱・電池・アプリサイズが課題。
  - 現実的なのは**役割分担（ハイブリッド）**。
    - ローカル: 軽い判定（例: ToDo っぽい発話か、クラウドに送るべきか）や、他人の発話の処理
    - クラウド（Claude）: 調査・助言などの重い処理
  - ADR-0002 の選択肢 C（他人の発話は端末内で処理）の実現手段にもなる。
- **次の一手:** 端末内で動かしたい処理を洗い出す → 候補モデル・ランタイムを iPhone 15 で動かせるか調べる。

### B-14 通話中の音声も拾いたい
- **要望:** 通話中は録音ができない。通話の内容も拾って処理したい。
- **優先度:** 未定
- **メモ:**
  - ⚠️ iOS では、**他社アプリが電話の通話音声を取得する API は無い**。通話が始まるとこのアプリの録音は中断される。通話アプリ用の CallKit も、他のアプリの通話音声は扱えない。
  - 考えられる代替案（どれも要調査）:
    1. **iOS 標準の通話録音を使う。** iOS 18 以降は電話アプリ自体に通話録音・文字起こし機能があり、録音すると相手にも通知される。その文字起こしや録音を、ユーザーがこのアプリに共有する（手動）。日本で使えるか・共有できる形式は未確認。
    2. 通話の後に、ユーザーが要点を口頭でエージェントに伝える（「さっきの電話で〜を頼まれた」→ ToDo 化）。技術的には今すぐ可能。
    3. スピーカー通話にして本体マイクで拾う → 品質と、OS が録音を許すかが不明。プライバシー面の問題も大きい。
  - **プライバシー:** 通話相手の発言を扱うことになる。ADR-0002（本人の発話だけクラウドへ）と衝突するので、扱うなら方針（相手への告知・同意、端末内処理）を ADR で決め直す必要がある。
- **次の一手:** 案 1（iOS 標準の通話録音 → 共有）が日本で使えるかと、取り出せる形式を調べる。
