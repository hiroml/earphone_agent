# ADR-0002: クラウド LLM には本人の発話の文字起こしだけを送る

- ステータス: 提案中
- 日付: 2026-11-23
- 関連: open-questions Q5, Q6、[spec: agent-core](../specs/agent-core.md)、CLAUDE.md §6

## コンテキスト
エージェントの推論には Claude API（クラウド）を使う。一方、イヤホン・スマホのマイクは第三者の声も拾う。CLAUDE.md では「生音声は原則端末外に出さない」としているが、文字起こしテキストの扱いは決めていなかった。

## 選択肢
### A. 本人の発話の文字起こしだけを送る
- 長所: 第三者のデータがクラウドに出ない。同意の問題が小さい。話者判別が「エージェントを呼ぶ入口」を兼ねる。
- 短所: 「他人に頼まれたことを ToDo 化する」（vision U1）が、そのままではできない。話者判別の精度に依存する。

### B. すべての文字起こしを送る
- 長所: 会話全体から ToDo を抽出できる。
- 短所: 第三者の発言を本人の同意なくクラウドに送ることになる。法的・倫理的リスクが大きい。

### C. 他人の発話は端末内で処理する
- 長所: U1 を実現しつつ、第三者のデータは外に出ない。
- 短所: 端末内 LLM の性能・電池の制約がある。

## 決定
当面は A を採用する。U1 は、C を検証できるまで保留とする。

## 理由
プライバシーを最優先の評価軸としているため（CLAUDE.md §6）。話者判別の PoC 結果によっては見直す。

## 影響
- `earagent.utterance.may_send_to_cloud` で強制する（テストあり）。
- 判定不能（UNKNOWN）は送らない側に倒す。
- 話者判別の精度が低いと、本人の依頼が無視されることがある。iOS PoC で精度を測る。
- 送信先のクラウド LLM には Sarashina API（SB Intuitions）も加わった（比較用）。同じゲートを通す。データ保持・学習利用の規約は未確認なので、本番で使う前に確認する。
